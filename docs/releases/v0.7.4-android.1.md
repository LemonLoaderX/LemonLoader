**Breaking update:** this release changes Android Mod APIs and the installation
contract. The `0.7.4` base follows upstream MelonLoader; it does not imply Android
compatibility with `v0.7.3-android.7`. Use LemonLoader.Patcher **2.0.0 or later**
when preparing this payload with Patcher. Manual installation remains supported.

## Breaking changes and migration

| Affected use | Change | Required migration |
| --- | --- | --- |
| Mods using Java | `MelonLoader.Java` JNI/JObject/JClass/JValue and member-ID APIs, including their compatibility shims, are removed. | Rebuild against the current Loader and pinned `Java.Interop.dll`, using `Java.Interop` peers and `MelonLoader.Android` bindings. Follow the [JNI migration guide](https://github.com/LemonLoaderX/LemonLoader/blob/v0.7.4-android.1/docs/android/JNI.md#exceptions-and-migration). |
| Android Mod builds | New Android Mods target `net10.0`; the supplied runtime is .NET 11. The historical `loader/net6` directory is only an installation path. | Update project references and disable Copy Local for Loader/Java.Interop. Do not ship a second Java.Interop runtime. Mods that do not use removed APIs are not automatically incompatible, but still need validation against the game's current Interop. |
| Payload installers | Current payloads use layout 9. Layout 8 and external crypto-helper DEX releases are retired. | Use the complete current Release and its matching runtime profile. Android crypto helpers are embedded in `libmain.so`; do not append an old helper DEX or mix old runtime files into the new payload. |
| Installed metadata consumers | Installer-generated revision, tree-hash and runtime/Interop identity files are no longer required installed inputs. | Follow the [payload contract](https://github.com/LemonLoaderX/LemonLoader/blob/v0.7.4-android.1/docs/android/ARTIFACTS.md). Do not require or regenerate removed metadata when editing installed payloads. Release validation, ZIP safety, ABI and runtime completeness checks remain required. |
| Source automation | Loader owns its dependency pins, preparation, build and verification commands. Retired parent-container scripts and submodule layout are not build inputs. | Run the maintained [Loader commands](https://github.com/LemonLoaderX/LemonLoader/blob/v0.7.4-android.1/scripts/README.md) from this repository. CoreCLR 10 maintenance workflows are retired. |

For an existing game installation:

1. Retain the original APK, signing material and user Mod/configuration data.
2. Prepare a fresh payload from the original game APK with the matching Release
   and Interop DLLs generated for that exact game. Do not feed an already-patched
   installation into Patcher or merge old and new runtime trees.
3. Migrate Mods that use removed APIs. Preserve the existing application package
   and signing identity, then apply a replacement update; uninstalling or clearing
   app data is not part of this migration.

See [installation](https://github.com/LemonLoaderX/LemonLoader/blob/v0.7.4-android.1/docs/android/USAGE.md) and [deployment policies](https://github.com/LemonLoaderX/LemonLoader/blob/v0.7.4-android.1/docs/android/DEPLOYMENT.md)
before packaging user files. An APK update drives runtime extraction; editing an
APK in place without an Android package update is not an extraction refresh.

## Changes included

- Java.Interop-based hosting, typed bindings, scoped references and callbacks.
- Embedded Android crypto helpers, previous-session logs, CoreCLR crash-report
  retention and Android system-exit evidence.
- Source-fork fixes for owned near-trampoline storage, shared-page permissions,
  ARM64 native exception slots, atomic MethodDesc flags and native proxy HFA layout.
- Best-effort early near allocation: failure to reserve capacity no longer blocks
  game initialization. Actual hook installation failures still report errors.
- Editable payloads and streamlined startup without installer metadata scans.

## Known limitations

Intermittent SceneManager hook failures and some TLS EOF/timeouts remain
unresolved. ReadyToRun is not enabled in production. Android's synchronous HTTP
restriction remains; use asynchronous HTTP or evaluate the Bionic profile for
Mods that require synchronous requests.

Controlled secondary-Activity recreation does not establish support for recreating
the original Unity Activity. API 26 devices, physical 16 KiB-page devices, additional
games/Unity versions and OpenSSL review remain separate qualification work.
The incomplete macOS ARM64 JIT-copy adapter is withdrawn; this Android release
does not claim new macOS hardware qualification.
