**Installer compatibility:** these archives use Release manifest format **3**.
Use [LemonLoader.Patcher 2.1.0 or later](https://github.com/LemonLoaderX/LemonLoader.Patcher/releases/tag/v2.1.0).
Patcher 2.0.0 cannot read the new archives. Installed payload layout remains **9**;
this update does not introduce another Mod API migration.

## Upgrade notes

- The Release manifest removes redundant RID, ABI, profile, backend and build
  labels. The verified file inventory retains sizes and SHA-256 hashes. Custom
  installers should follow the [format-3 contract](https://github.com/LemonLoaderX/LemonLoader/blob/v0.7.4-android.3/docs/android/ARTIFACTS.md#release-inputs-and-apk-layout).
- Android no longer includes generator-only dependencies or writes the inactive
  `disable_start_screen` and `keep_cpp2il_output` configuration fields. Existing
  active settings remain supported; Interop generation stays off device.
- Development Interop deployment accepts ordinary DLLs and verifies staging
  before replacement, with guarded recovery after transfer or publication failure.
  See the [deployment procedure](https://github.com/LemonLoaderX/LemonLoader/blob/v0.7.4-android.3/docs/android/INTEROP.md#refresh-an-installed-development-build).

Prepare updates from the original game APK, use matching game Interop, and keep
the existing package and signing identity. Follow the [installation guide](https://github.com/LemonLoaderX/LemonLoader/blob/v0.7.4-android.3/docs/android/USAGE.md).

## Known limitations

MuMu and other native-bridge configurations may fail with `DobbyHook -1` when no
owned or unmapped page is available within ARM64 short-branch range. This release
does not restore unsafe takeover of another allocator's reserved memory or claim
that emulator limitation is fixed. Physical ARM64 startup validation does not
establish support for every game, emulator or 16 KiB-page device.
